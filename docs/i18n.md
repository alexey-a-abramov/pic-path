# Internationalization (i18n)

Pic Path is translated into multiple languages so it works for developers wherever
they live. This document explains the layout, what is and isn't translated, and how
to contribute.

## Status

| Tier | Languages | What this means |
|---|---|---|
| Source | English (`values/`) | Authoritative. Every string lives here first. |
| **First-tier (fully translated)** | `zh`, `es`, `pt`, `ru`, `ja`, `de`, `fr`, `ko`, `hi`, `tr` | Every key in the source file has a translation. |
| Partial (community) | `ar`, `bn`, `fa`, `gu`, `it`, `jv`, `kn`, `ml`, `mr`, `my`, `or`, `pa`, `pl`, `ro`, `ta`, `te`, `uk`, `ur`, `vi` | Older translations covering the original ~41 strings; missing newer keys fall back to English. PRs welcome. |

The 10 first-tier languages were chosen by approximate share of the global software
developer population. `values-zh` is treated as Simplified Chinese (largest dev pool);
splitting into `zh-rCN` / `zh-rTW` is a separate decision and not done here.

> **First-pass translations were generated by an LLM.** They're functionally correct
> for UI strings (short, well-bounded, low context) but may read stilted to a native
> speaker. Native-speaker review is welcome via PR — see "How to update an existing
> language" below.

## File layout

```
app/src/main/res/
  values/strings.xml          # English — source of truth
  values-zh/strings.xml       # Simplified Chinese
  values-es/strings.xml       # Spanish
  values-pt/strings.xml       # Portuguese
  values-ru/strings.xml       # Russian
  values-ja/strings.xml       # Japanese
  values-de/strings.xml       # German
  values-fr/strings.xml       # French
  values-ko/strings.xml       # Korean
  values-hi/strings.xml       # Hindi
  values-tr/strings.xml       # Turkish
  values-XX/strings.xml       # ...partial locales
```

Android picks the closest match for the user's system locale and falls back to
`values/strings.xml` for any key missing in the chosen locale. Missing keys are
*never* a build error — they're a runtime fallback.

## Hard constraints

These will silently break the build or the app if you miss them. Read before editing.

### 1. Format args must be byte-identical

Anywhere the English string contains `%1$s`, `%2$d`, `%1$.2f`, etc., the translated
string must contain the same tokens — same indexes, same conversion characters, same
`$` between index and type.

```xml
<!-- English -->
<string name="copy_selected">Copy %1$d paths</string>

<!-- OK: re-ordered, same tokens -->
<string name="copy_selected">%1$d 路径已复制</string>

<!-- BROKEN: missing $ — Android throws at runtime -->
<string name="copy_selected">%1d 路径已复制</string>
```

### 2. Don't translate brand tokens

Leave these verbatim in every locale:

`Pic Path`, `Claude`, `Gemini`, `Codex`, `Termux`, `GitHub`, `MIT License`, `Android`.

### 3. Escape XML reserved characters

| Character | Escape |
|---|---|
| `'` (apostrophe) | `\'` |
| `"` (quote) | `\"` |
| `&` (ampersand) | `&amp;` |
| `<` | `&lt;` |
| `>` | `&gt;` |

The English file uses `You\'re up to date!` for that reason. Same rule applies to
every translation.

### 4. Don't clobber existing translations

The partial-tier locales (`it`, `pl`, `vi`, etc.) have hand-tuned strings from earlier
contributors. When adding the missing keys, **append**; don't rewrite the whole file.

## How to add a new language

1. Pick the [Android locale qualifier](https://developer.android.com/guide/topics/resources/providing-resources#LocaleQualifier)
   (e.g., `nl` for Dutch, `pt-rBR` for Brazilian Portuguese specifically).
2. Create the directory: `app/src/main/res/values-XX/`.
3. Copy `app/src/main/res/values/strings.xml` into it.
4. Translate every value while leaving every `name` attribute untouched.
5. Build: `./gradlew assembleDebug`. Any XML error names the offending file.
6. Test on device — see "Verification" below.
7. Open a PR. Add the language to the "Status" table above.

## How to update an existing language

To find what's missing in, say, `values-it/`:

```bash
comm -23 \
  <(grep -oP 'name="\K[^"]+' app/src/main/res/values/strings.xml | sort) \
  <(grep -oP 'name="\K[^"]+' app/src/main/res/values-it/strings.xml | sort)
```

That prints every key present in English but missing in Italian. Translate just those
keys and append them to `values-it/strings.xml`. Don't touch the keys that are
already there.

To improve an existing translation, edit it in place and explain the change in the
PR description (single character "fixes" without rationale are hard to review).

## Verification

After editing:

```bash
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Then change the device language to your locale and open the app:

- **System Settings → System → Languages**: drag your language to the top.
- Or in Pic Path itself: **Settings → Language**.

Walk through the app: grid, fullscreen viewer, editor, settings. Look for:

- Strings that overflow or wrap awkwardly (Compose Text uses `Ellipsis`, but a really
  long translation may still look bad — consider a shorter phrasing).
- Strings that didn't translate (still in English) — usually means a key was added
  to `values/strings.xml` after your translation.
- Format-arg crashes (the app force-closes on the screen that uses the broken string).

## What's *not* translated

- The strings file is UI only. README and other docs stay in English.
- Brand and product names (see constraint #2).
- Format placeholders, file paths, identifiers in error messages destined for logs.

## Adding new strings (for code contributors)

When you add a new `<string>` to `values/strings.xml`, **don't** add it to every
locale yourself. The CI / next translation pass picks it up. The only thing you must
do is make sure the English string:

- Uses positional format args (`%1$s`, `%2$d`) when there's more than one — never
  bare `%s %s`, which can't be re-ordered in translation.
- Avoids `/* ... */` runs in Kdoc-style XML comments above strings (Kotlin allows
  nested block comments and the resource compiler is unforgiving about half-closed
  ones).
- Doesn't bake in English word order assumptions ("Copy %1$d paths" — fine; "Copy
  the following %1$d items" — burns in English-style plurals; consider Android's
  [plurals resource](https://developer.android.com/guide/topics/resources/string-resource#Plurals)
  for those).
